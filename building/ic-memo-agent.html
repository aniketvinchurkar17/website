Built

IC Memo Auto-drafter

Type a company name. Get a structured investment committee memo back in about two minutes.

Aniket Vinchurkar

I wanted to know how much of a junior analyst’s diligence workflow an autonomous agent could actually do — not the summarising, which is easy, but the part where you decide what to look into next. So I built it and watched where it broke.

What it does

You give it a company. It researches it across the web, drafts a two-page IC memo — TL;DR, business, market, team, traction, thesis, risks, comparables, open questions — and then criticises its own draft. A typical run is 60 to 180 seconds and 8 to 15 autonomous tool calls.

Three agents, each with one job:

  • Researcher. Runs in a loop with web search and page fetch, deciding what to pull on and when it has enough.
  • Writer. Turns the research into the memo.
  • Critic. Reads the memo as a sceptical IC partner and flags missing data, weak claims and unsupported recommendations.

Why it is actually agentic

Most things labelled AI tools are a single call: prompt in, text out. This isn’t, and the difference is the Researcher’s loop. It plans an opening set of queries, reads what comes back, judges whether a result is useful or marketing copy, pivots when a thread dead-ends, fetches the full page when a snippet looks promising but incomplete, and decides for itself when to stop.

There is no hardcoded workflow. It can hit a dead end and recover, and it triangulates across sources rather than trusting the first one. On the sample run it made eleven tool calls in 142 seconds and the trace is in the repo, so you can see what it chose to chase.

What it will not do

This is the part I care about, because a diligence tool that overstates itself is worse than no tool.

  • Public data only. No private financials, no cap tables, no founder calls.
  • It does not model. The memo says “revenue: not disclosed” rather than inventing a number. That is deliberate. A fabricated figure in an IC memo is worse than a blank.
  • The critic does not re-trigger research. It flags the gap; it doesn’t go fill it. That loop is the obvious v2.
  • Search depth is the ceiling. A broad web index is not Crunchbase or Tracxn. A production version would plug into those, plus MCA filings for Indian companies.

What I would build next

Close the critic-researcher loop so a flagged gap triggers targeted re-research. Add screening: give it a sector thesis, get back a ranked list of twenty companies with a one-pager each. Add a diff mode that re-runs on the same company six months later and reports only what changed — which is the version I would actually use.

Python, Claude with tool use, Tavily for search, Streamlit for the UI. Source and a full sample run on GitHub.
